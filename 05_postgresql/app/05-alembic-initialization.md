 Alembic is the standard database migration tool for SQLAlchemy, and it pairs naturally with FastAPI when you're using SQLAlchemy as your ORM. Here's a practical guide to integrating Alembic with FastAPI.

## 1. Install Dependencies

```bash
uv add fastapi sqlalchemy alembic psycopg2-binary  # or your DB driver
```

## 2. Initialize Alembic

```bash
uv run alembic init -t async migrations
```

This creates:
- `alembic/` — migration scripts directory
- `alembic.ini` — configuration file

## 3. Configure `alembic.ini`

Point Alembic to your database URL:

```ini
# alembic.ini
sqlalchemy.url = postgresql://user:pass@localhost/dbname
```

Or use an environment variable in `alembic/env.py` instead (recommended for real projects).

## 4. Configure `alembic/env.py`

Import your SQLAlchemy `Base` and models so Alembic can autogenerate migrations:

```python
# alembic/env.py
from logging.config import fileConfig
from sqlalchemy import engine_from_config, pool
from alembic import context
import os
import sys

# Add your project root to path
sys.path.append(os.path.dirname(os.path.dirname(__file__)))

from app.database import Base  # Your declarative base
from app.models import *       # Import all models so they're registered

# Alembic Config
config = context.config

# Override with env var if present
db_url = os.getenv("DATABASE_URL")
if db_url:
    config.set_main_option("sqlalchemy.url", db_url)

if config.config_file_name is not None:
    fileConfig(config.config_file_name)

target_metadata = Base.metadata  # Critical for autogenerate


def run_migrations_offline() -> None:
    url = config.get_main_option("sqlalchemy.url")
    context.configure(
        url=url,
        target_metadata=target_metadata,
        literal_binds=True,
        dialect_opts={"paramstyle": "named"},
    )
    with context.begin_transaction():
        context.run_migrations()


def run_migrations_online() -> None:
    connectable = engine_from_config(
        config.get_section(config.config_ini_section, {}),
        prefix="sqlalchemy.",
        poolclass=pool.NullPool,
    )
    with connectable.connect() as connection:
        context.configure(
            connection=connection, 
            target_metadata=target_metadata
        )
        with context.begin_transaction():
            context.run_migrations()


if context.is_offline_mode():
    run_migrations_offline()
else:
    run_migrations_online()
```

## 5. Your FastAPI Database Setup

```python
# app/database.py
from sqlalchemy import create_engine
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import sessionmaker
import os

DATABASE_URL = os.getenv("DATABASE_URL", "postgresql://user:pass@localhost/dbname")

engine = create_engine(DATABASE_URL)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

Base = declarative_base()

# Dependency for FastAPI
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

## 6. Create a Model

```python
# app/models.py
from sqlalchemy import Column, Integer, String
from app.database import Base

class User(Base):
    __tablename__ = "users"
    
    id = Column(Integer, primary_key=True, index=True)
    email = Column(String, unique=True, index=True)
    hashed_password = Column(String)
```

## 7. Create & Run Migrations

```bash
# Generate migration automatically from models
alembic revision --autogenerate -m "add users table"

# Apply migrations
alembic upgrade head
```

## 8. Use in FastAPI Endpoints

```python
# app/main.py
from fastapi import FastAPI, Depends, HTTPException
from sqlalchemy.orm import Session
from app.database import get_db
from app.models import User

app = FastAPI()

@app.get("/users/{user_id}")
def read_user(user_id: int, db: Session = Depends(get_db)):
    user = db.query(User).filter(User.id == user_id).first()
    if not user:
        raise HTTPException(status_code=404, detail="User not found")
    return user
```

## Key Best Practices

| Practice | Why |
|----------|-----|
| **Never use `Base.metadata.create_all()` in production** | Alembic manages schema evolution; `create_all` bypasses migrations |
| **Always review autogenerated migrations** | Alembic misses some changes (e.g., column renames, certain constraints) |
| **Pin your migration versions** | Use `alembic upgrade +1` or specific revision IDs in CI/CD |
| **Keep `target_metadata = Base.metadata`** | Without this, `--autogenerate` produces empty migrations |
| **Use `env.py` for dynamic DB URLs** | Don't hardcode credentials in `alembic.ini` |

## Common Commands

```bash
alembic current          # Show current revision
alembic history          # Show all migrations
alembic downgrade -1     # Rollback one migration
alembic stamp head       # Mark DB as current without running migrations
```
